## EXT-001 [HIGH] 2026-10-27 15:23 — 启动交接：需求、架构、阶段计划

### 用户需求（原话要点）
1. 做一个 Chrome 插件，能装进 Chrome 浏览器。
2. 浏览器播放在线视频流或本地视频文件时，抓取视频的音频流，交给本机软件做 ASR → 翻译 → TTS。
3. TTS 的音色要克隆音频流里说话人的音色。
4. 处理有时延，可以把视频缓冲一段时间（例如 10 s）再播放，保证音画同步。
5. ASR 抓音频时要带时间戳，TTS 音频按原声同样的时间和画面同步。
- 用户已选：首版支持**任意网页视频（抓整个标签页）+ 本地文件**。DRM 站点（如 Netflix）会被浏览器黑屏，**明确不支持**，界面上要提示。

### 总原则（继承，不得违反）
- 引擎复用现有交付版本，**不改其他模块的文件**：ASR R2T2 INT8 @ GPU.0；MT Hy-MT2 INT8 @ GPU.0；TTS Qwen3-TTS 全 NPU。只在 import 或复制适配层的范围内复用。发现引擎需要改动，写进 STATUS，由主会话转给对应模块。
- 不在 CPU 上跑推理（CPU 只能做单组件诊断）。CUDA 不作默认。
- TTS 连续合成、内存缓存、**不丢句**。克隆音色只放内存，不落盘。
- 和实时字幕 App 互斥：两者抢同一套设备，桥接服务启动时检测到 App 在运行，就提示并拒绝启动。
- 计时作业持 C:\Users\Trekker-PTL\shared\MACHINE_LOCK（只能排队，不能删别人的锁）。测试素材：260902_SPE 前 5 分钟（做成"静态图 + 音轨"的 mp4 当本地文件），以及一个公开的英文视频网页。

### 架构（主会话建议，可以提出更好的方案，但要给数据）
**A. Chrome 插件（Manifest V3）**
- popup：开始/停止、目标语言、延迟 D（默认 10 s，可调 6–20 s）、音色（克隆说话人 / 预设 A）、原声压低量（默认 −15 dB）、字幕开关、桥接连接状态。
- 抓取：用户点开始 → chrome.tabCapture.getMediaStreamId → offscreen document 里 getUserMedia(chromeMediaSource:'tab') 拿到整页的音视频流。被抓的标签页原声会被静音，用户只听到我们延迟后的输出。
- 本地文件：插件自带播放器页面用 file picker 打开，用一个**隐藏的 video 元素**当源（captureStream），和网页走同一条管线。
- 音频上行：AudioWorklet 重采样到 16 kHz 单声道 PCM16，每帧 20–100 ms，通过 WebSocket 发到桥接服务。每帧带 {seq, sample_index}。**时间戳用累计采样数换算**（不用墙钟，避免漂移），会话起点为 t0。
- 延迟画面：在插件播放窗口（独立窗口或标签页）里，视频轨经 MediaStreamTrackProcessor → VideoEncoder（硬件 H.264/VP9）→ 已编码块的环形缓冲（带时间戳）→ 延迟 D 后 VideoDecoder → canvas。原声经 Web Audio DelayNode(D) 加压低增益。**画面和原声都用同一个 AudioContext 时钟**。备选方案：MediaRecorder 分块 + MSE，精度差一些，只作兜底。
- 配音播放：收到 TTS 句子 {id, t_start, t_end, pcm} 后，用 AudioBufferSourceNode.start(t0 + t_start + D) 精确排程。配音期间对原声做 ducking。字幕覆盖层同样按时间排程。
- 暂停或拖动进度：首版规定为暂停时两边一起暂停；拖动进度条 → 清空会话，重新开始（在 UI 上提示）。

**B. 本地桥接服务（Python，dub_server.py）**
- 只绑 127.0.0.1，WebSocket。安全：校验 Origin = chrome-extension://<本插件 id>，并用首次配对生成的 token 鉴权。
- 管线：PCM（带 sample_index）→ 分段（先用 R2T2 现有的断句；ASR-013 的 pyannote 断句交付后再切换）→ ASR 定稿段 [t_start, t_end]（按采样计数）→ MT（以 ASR 定稿段为翻译单元；如果 MT 合并了几段，时间区间取并集）→ TTS（NPU，按说话人选音色）→ **时长适配**：目标时长 = t_end − t_start，可以占用到下一段开始前的静音；超长时在服务端做保持音高的变速（WSOLA 等，不能用 playbackRate，那会变调），上限 1.25×；超出上限就允许顺延，并记录顺延量 → 下发 {id, t_start, t_end, src, tgt, spk, pcm24k}。
- 音色克隆：按说话人取 x-vector（复用 TTS-019 的 embed_speaker 和 ASR-013 的说话人 id）。某个说话人攒够 ≥ 3 s 干净语音之前，用预设 A。那两条还没交付时，P1 先用"整段视频单一说话人：取开头第一个 ≥ 3 s 的段"做简化克隆。背景音乐会影响声纹和 ASR，人声分离留到以后评估，先记录影响。
- 启动方式：桌面快捷方式启动桥接（pythonw，**按用户的启动方式验收**，吸取 APP-023 的教训）。popup 显示连接状态。Native Messaging 只作可选的"自动拉起"，不是首版必需。
