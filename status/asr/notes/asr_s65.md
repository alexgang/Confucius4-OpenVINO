## 2. 🔴 D7 —— asr090 的章节行数门禁只覆盖 §64，且**算法用错口径**

### 实测

- ASR-036 明文：「每个新章节 **≤ 60 行**」。
- `asr090` 的实现：**只**判 `§64 <= 60 行`；**§63 = 70 行**只打 `INFO`，**不判失败**
  ⇒ ⇒ **超限章节仍能通过「独立复核 ALL PASS」** ⇒ 门禁有盲区。

### 🔴 口径问题（§64 已立「引用行数必须带口径」的铁律，`asr090` 未落实）

- `asr090` 的章节行数算法 = `end - k`（**含尾部空段**）；
- §64 实测口径（正文行数，不含尾部空段）：§62 = 54 / §61 = 8 / §60 = 8 / §63 = **70** / §64 = **55**（正文口径）；
- 但 `asr090` 打印的 §64 = **56**（含尾空段口径）、§63 = **70**（§63 后接 §64 ⇒ 无尾空段 ⇒ 两种口径同值）
  ⇒ **同一文档里两种口径混用** ⇒ 换个章节位置就得出不同的数。

### ✅ 修法

新守卫 `asr093` 判**每一个**章节（不限编号）≤ 60 行，**统一用正文口径**（去尾部空段）
⇒ 超出即 FAIL；§63 属**已提交旧章节**⇒ 判 **INFO + 显式标注「历史超限」**，**不静默放过**。

### 🔴 写入脚本干跑抓到的自身 bug（本轮新增，铁律再确认）

1. **令牌替换写在真值点迭代之外** ⇒ 替换改变正文长度 ⇒ 真值点算出的字节数**立刻过期**
   ⇒ **令牌替换必须在真值点迭代之前**（§62 首次踩的同一个坑，**第 2 次复发**）。
2. **§62 未从精简版移除** ⇒ 「最近章节」变成 **4 节** ⇒ 被自检拦下。
3. **干跑阶段无条件写归档** ⇒ **污染了真实归档**（`git checkout` 还原后 md5 复原）
   ⇒ 修法：归档**在 STATUS 自检通过之后**才写；干跑只改内存副本。
4. **章节比对越界**（备份里没有 §65 ⇒ `next(...)` 抛 `StopIteration`）⇒ 加默认边界。
5. 🔴 ⇒ **干跑确实有效**：5 次干跑共抓出 **4 个自身 bug**，且**真实 STATUS 直到转绿才被写**。
