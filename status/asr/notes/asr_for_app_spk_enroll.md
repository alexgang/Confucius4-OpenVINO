# 给 App 的说话人登记说明（≤1 页）— ASR-049 ① ②

> 给 App 线程（`APP-071` 克隆串人 / `APP-076` 同步 `min_clean_ratio` 0.6）。**ASR 只给口径，不改 App 代码**；是否采用**由 App 决定**。明细长文：`status/asr/notes/asr_s76.md`（241 行）。

**0. 直接回答 APP-071（3 行）**
① **`spk_conf=0.129` = 与已登记者的最大余弦相似度，低 = 新人的正常表现** ⇒ **不构成「该段音频不能用」的依据**（新说话人实测 conf = 0.129/0.101/0.0833/0.0153/−0.0446）。② 该段能否登记**只看三件事**：clean 累计时长 ≥ **1.5 s**；该段**是否跨换人点**；overlap 帧是否在 `clean_ranges` 里 ⇒ **当前无法判**（overlap 参数惰性，§2 坑 1）。③ **推荐方案 B**（§3：等**第二段**再登记 + 只取**最靠后**的 clean 区间），**保留 App 现有 `REG_CONF_MIN` / 干净连续 ≥2.5 s**；理由：边界段的 clean 区间**结构上无法排除上一人**，「第二段」几乎必然整段属于新人 ⇒ 污染比例由 **§4 原方案**降到 **§4 改进值**。**最终由 App 决定。**

**1. `spk_conf` 的确切含义（低 ≠ 标签错）**
定义：该段嵌入与**已有簇心**的**最大余弦相似度**（`asr052_spk_runtime.OnlineSpeakerCluster.assign()`：`sims=[dot(u,c)]`→`argmax`）。| 情形 | 值 | 含义 | |---|---|---| | 第一个簇 | **1.0** | `assign()` 直接返回 `('S1',1.0,'init')`，**不是相似度** | | 命中已有簇 | 0.4–0.9 | 与该簇心的相似度 | | **新说话人**（<`thr`=0.35） | **0.129/0.101/0.0833/0.0153/−0.0446** | **「与所有已登记者都不像」⇒ 判为新人** |
🔴 **低 ≠ 标签不可信**，而是「疑似新人」⇒ 该查「**第一次登记用的音频段选对没有**」（§3），不是「标签准不准」。

**2. `clean_ranges` 的定义/单位，以及两个必须知道的坑**
定义：段内 `p_speech ≥ 0.5` 的**连续区间**，长 **≥ 0.3 s** 才保留（`asr052_speaker_tracker_api._clean_ranges`）｜单位：**秒**、**全局时间轴**、`(start_s,end_s)` 列表｜App 怎么拿：✅ **现有 API 已返回**（桥接层白名单内，`live_caption/speaker_tracker.py` 的 `on_final`/`poll_results`）⇒ **不需内核新增字段**｜登记取样：App `_spk_pcm_for()`→`pcm_for_ranges(rngs)` ⇒ **只切 clean 区间**。
🔴 **坑 1：`clean_ranges` 不保证单人**（重叠语音帧**没被排除**）。`overlap_ratio_max` 是**惰性参数（永不触发）**：`p_dom` 只取 powerset **单人三类**（`SINGLE_CLASSES=(1,2,3)`）⇒ 行和 ≤ 1.0 ⇒ `>1.05` **恒 False** ⇒ `overlap_ratio` **恒 0.0** ⇒ 分支永不执行（产物 `asr121_overlap_clean_diag.json`：20000 次数值复刻 = 0.0，反证并入重叠类 = 0.61835）⇒ **一个 clean 区间可能同时有两人在说话**。⚠️ **不要把 `overlap_ratio_max` 当作「已排除重叠」的防护**；修复＝**新开发量** ⇒ **列待用户决定，ASR 未自行改**。
🔴 **坑 2：`is_new_spk` ≠「新说话人」**：语义 =「与上一段标签不同」（`is_new = spk != prev_spk`）⇒ 实测 **29** 次 vs 真值换人点 **26** ⇒ **3 次是拆分/回切误触发** ⇒ App 的「`is_new_spk` ⇒ 取样一次」在同一人被拆成两个 ID 时会**误触发**。

**3. 三个登记方案（推荐 B）**
| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A（原方案）** | 首次 `is_new_spk` 段 ⇒ 取**全部** `clean_ranges` | 延迟最低 | **换人边界段混入上一人**（§4） |
| **B（推荐）** | 首次**不登记**，等该 spk **第二段**；且**只取时间上最靠后**的 clean 区间 | 污染比例最低 | **首句延迟** |
| **C** | ASR 新增「段内按**帧级主导说话人**切分」 | 最彻底 | 🔴 **新开发量**（需完整 7 类 `p_dom`，现截成 3 类）⇒ **不在本轮** |

无论选哪个：登记仍按 **`REG_CONF_MIN`** / **干净连续 ≥2.5 s**（`APP-075`）。🔴 **ASR-050 后标签会变多**（`min_clean_ratio` 0.8→0.6）⇒ **标签多了 ≠ 这段可拿来登记克隆音色**。

**4.「换人边界段混入上一人」实测比例（ASR-049 第 3 项）**
产物 `asr125_spk_enroll_contamination_v2.json`（+ 复核 `asr126_contam_zero_recheck.json`）；口径：900 s 评测集（3 clip/136 段）、基线参数（`min_clean_ratio=0.8`）、真值 = 评测集自带 **ASR-028 人工核对** `ref_segments`（**主口径**），RTTM（pyannote 3.1 **伪真值**）**交叉核对**。
**原方案（A：首次登记段取全部 `clean_ranges`）= 0.0**（N = **0.0 s** / 分母 **22.545 s**）；**改进（B：只取最靠后区间）= 0.0**（N = 0.0 s / 分母 27.511 s）；**改进（C：等第二段再登记）= 0.0**（N = 0.0 s / 分母 27.545 s）。
🔴🔴 **这 3 个 0 只能在评测集成立，不能外推到生产**：① `asr126` 用**注入反证**证明判据**有鉴别力**（把 clean 区间**平移进**真值上一说话人区间 ⇒ 比例变 **1.0**；把 prev 区间清空 ⇒ 变 **0.0**）⇒ **不是假 0**；② 但根因是**评测集切段用人工段界**（`ref_segments` **每段 1 个 spk**）⇒ **9/9** 个首次登记段的起点**恰好等于**真值上一说话人区间的终点 ⇒ 该段 clean 区间**天然**全属新人 ⇒ **0 是结构性必然**；③ **生产环境由静音规则切段（最短 6 s）、段边界常落在换人点内侧** ⇒ **生产下的真实污染比例 > 0** ⇒ 🔴 **ASR 给不出生产的污染比例** ⇒ 第 0 条 ③ 的推荐按**定性结论**读（边界段**结构上**无法排除上一人 ⇒ 方案 B 仍有价值），**不按 0 读**。

**5. 字段清单（App 现有 API 已有，无需改内核）**
`spk` ✅ **到达序编号**（🔴 跨臂/跨会话**不可直接比**，要稳定身份得自建映射）｜`spk_conf` ✅ 与已登记者的最大余弦相似度（**低 = 新人**）｜`is_new_spk` ✅「与上一段不同」（**非**「从未出现」）｜`clean_ranges` ✅ **秒/全局时间轴**，干净连续区间（≥0.3 s）⇒ **登记取样用它**｜`pending`/`reason` ✅ 标签是否晚到 / 未出标签原因｜`clean_ratio` ❌ 内核**算了**但**被桥接层白名单丢弃** ⇒ 读到必然 `None` ⇒ **可由 `clean_ranges` 自算**（`Σ(b−a)/段时长`）｜`overlap_ratio` ❌ 同上被丢弃，**且即使转发也是 0.0**（惰性）⇒ **不要用它做决策**。
