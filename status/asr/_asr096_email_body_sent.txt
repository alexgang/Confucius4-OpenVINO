■ 4. 🔴 发现 B（比发现 A 更致命）：即使加上 --spk-bypass，旁路仍会拿不到任何标签 ⇒ 仍是零标签
机制（调用顺序错）：
  ext/speaker_bypass.py 的 _load()：
    L212  d = self._app_spk_dir()              → <root>/app/asr_spk
    L217  seg_ir, wes_ir = self._asset_paths() ← 此时 app/asr_spk 还没进 sys.path
    L225–226  os.sys.path.insert(0, d)        ← 路径注入在 _asset_paths() 之后
  而 _find_seg_for_window()（L85–104）靠 import asr052_spk_runtime 取 WIN_S ＋ from asr_spk_window import seg_ir_subdir_for 选变体，
  这两个模块只存在于 <root>/app/asr_spk/（实测 app\asr052_spk_runtime.py 不存在、app\asr_spk\ 下存在）。
  ⇒ L217 那一刻 import asr052_spk_runtime 抛 ModuleNotFoundError（实测 No module named 'asr052_spk_runtime'，且 sys.path 里没有任何 LiveCaption 路径）
  ⇒ 被 _find_seg_for_window 的 except Exception: return "" 静默吞掉
  ⇒ 回落 _find() 的旧顺序 ("fp32","fp16") ⇒ 选中 fp16（10 s 窗）

后果链（实测）：
  fp16 的 seg IR 输入长度 = 160000，而 rt.WIN_N = 80000（5 s 窗）
  ⇒ ASR-068 第 4 条新加的形状守卫直接拒绝（ext/spk_engine.py L224–227 RuntimeError）
  ⇒ 被 L252–254 的 except Exception 捕获 ⇒ _seg_error 置位、_seg_ready 永假
  ⇒ _advance_seg() 首行 if not self._ensure_seg(): return ⇒ 全程零分段帧 ⇒ 零标签

只读复刻 _load() 真实顺序的实测输出：
  STEP1 _app_spk_dir = …\app\asr_spk
  STEP2 _asset_paths seg = …\models\spk\pyannote_seg_3_0\fp16   ← 错，应为 fp16-w5
  STEP3 asr052_spk_runtime now importable, WIN_N = 80000

🟢 对照：App 侧同机器上是正确的 —— Confucius4_LiveCaption_v2.5\app\speaker_assets.py 的 find_seg_ir() 用 importlib 按文件路径加载
   app\asr_spk\asr_spk_window.py（不依赖 sys.path）⇒ 实测返回 fp16-w5（窗口 5.000 s，来源 asr_spk_window）⇒ App 对、EXT 错。

🟢 现成 workaround（我已实测有效）：_find_seg_for_window L88–90 让 EXT_SPK_SEG_IR 优先于所有探测
   ⇒ 设 EXT_SPK_SEG_IR=<包根>\models\spk\pyannote_seg_3_0\fp16-w5 ⇒ 实测 _asset_paths() 返回 fp16-w5、IR 输入长 80000 ⇒ 形状守卫放行。

🔴 建议修法（两处，任选或都做）：
   ① 把 sys.path.insert(0, d) 提到 _asset_paths() 之前（最小改动，直接修根因）；
   ② 或让 _find_seg_for_window() 改用 App 同款 importlib 按文件路径加载 asr_spk_window.py / asr052_spk_runtime.py（不依赖 sys.path）。
   这两处都在 ext/ 下，属你的分工，我方不代改。
