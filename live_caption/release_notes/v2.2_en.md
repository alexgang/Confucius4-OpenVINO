This section summarizes the changes in **v2.2** relative to **v2.1**.

> ⚠️ **v2.2 fixes the 6 problems reported by the user** (no CUDA audio / "no reference
> voice" offline / stutter / cloning about every 10 s / male voice played as a female
> voice / crowded layout). Models and plugin capabilities are **identical to v2.1**;
> **the desktop shortcut is not repointed yet** (decided after the user listens).

### ① TTS on CUDA produced no sound (fixed)

Two bugs stacked: the CUDA branch cached only the preset-A *reference audio* but not the
*voice name* ⇒ every fallback to preset A cleared the voice name ⇒ the pre-synthesis
voice check reported "no usable voice" ⇒ **every sentence failed** and no request ever
reached the CUDA sidecar.

Now: the CUDA branch caches the voice name as well; the fallback only swaps the
reference audio; the voice check for the CUDA backend asks whether a reference audio
currently exists.

### ② Offline reading reported "no reference voice" on CUDA (fixed)

Same root cause as ①. Added a regression case: CUDA backend + voice A ⇒ all 9 segments
succeed. Additionally, when the CUDA sidecar environment cannot be detected the **CUDA
option is greyed out with the reason shown** (instead of failing silently after the
user picks it).

### ③ Stutter (synthesis throughput ≤ playback consumption)

Measured: putting MT and TTS both on the NPU slows synthesis by 25–30 %; but even with
the default placement synthesis only reaches ≈1.0× real time while playback consumes
the buffer at 1.0–1.3× ⇒ the **ring buffer underruns**, which is the real cause.

Now:
* the session log prints a machine-readable telemetry line **every 30 s**
  (`asr_rtf / asr_backlog_s / mt_lat_p50 / tts_synth_rtf / uf_in_sentence_ms`);
* underflow is split into **in-sentence** (audible dropouts) and **idle** and converted
  to milliseconds;
* the **pre-buffer** uses `sentence length × (1 − 1/(r·speed))`;
* the playback speed is **dynamically capped** at `speed ≤ 1/r` (when synthesis cannot
  keep up it is better to lag than to drain the buffer by speeding up; the user's
  1.30× cap is unchanged);
* when MT/ASR and TTS share the NPU the voice section shows an **amber warning**
  (not a hard block).

### ④ Voice cloning changed from "every ~10 s" to "only on speaker change"

The old build ran **two cloning mechanisms at once** (a timed collector plus the
per-sentence binding) and the timed one was the active path ⇒ it re-cloned every ~15 s
regardless of speaker changes. The timed collector is now **disabled**; cloning only
follows the per-sentence rule: a new speaker is sampled from the first ≥1.5 s, frozen
after 3 s, and returning speakers reuse the cached voice.

### ⑤ A male voice was played back as a female voice (fixed)

Three root causes: the GUI **did not pass the clone flag** to the TTS service; the
late-label path **dropped the "new speaker" flag** (⇒ new speakers were never sampled);
and a missing label **always fell back to preset A**.
Now: the GUI passes the clone flag; new speakers are registered and sampled normally;
when the label has not arrived yet the **previous clone voice is kept** (preset A is
only used when no clone voice exists at all).

### ⑥ More compact layout

Controls that are rarely used (recognition language / draft translation / retry /
offline reading / test sound / show speaker / the three section notes) moved into a
**collapsible "Advanced" panel**; the three section notes are merged into the status
bar (visible on hover); the caption area grew from ≈30 % (v2.1) to **≈79 %** of the
window height (≥ 70 %); the minimum window width is 1024 with no clipped controls.
