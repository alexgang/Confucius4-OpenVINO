This section summarises the changes in **v2.1** relative to **v2.0**
(everything about v2.0 is listed in the sections below).

> ⚠️ **v2.1 is a "de-identified" rebuild of v2.0**: features, models and the
> web-dubbing plugin are **identical to v2.0**. The only change is that the
> build machine's real home directory and dev-directory paths no longer appear
> in the shipped files. The desktop shortcuts now point at v2.1.

### (1) Fixed the "absolute build-machine path" leak in the package

Three files under `ext/bridge/` documented the build machine's real home
directory and dev directories (e.g. `C:\Users\<build-user>\confucius4-openvino`).
Those strings are not executed, but the customer **can read them in the files**.

v2.1 replaces every such literal with a `<HOME>` placeholder:

* `ext/bridge/engines.py`
* `ext/bridge/segmenter.py`
* `ext/bridge/app_root.py`
* `app/speaker_assets.py` (an example inside a comment)

### (2) `ACCEPTED.json` now records the package path in `<HOME>` form

It used to record the absolute path on the build machine, which is wrong on
the customer's machine and leaks the build user name. It now records
`<HOME>\Confucius4_LiveCaption_v2.1`, so it stays correct on any machine.

### (3) Acceptance criterion fixed

The verification script used to look only at string literals in code and to
ignore comments — which is exactly why the problem in (1) slipped through.
It now scans the **whole file** (comments and docstrings included) and parses
binary `.lnk` files as UTF-16 as well.

### (4) Everything else is unchanged

Models, inference pipeline, the speaker-diarization bypass (off by default,
separate thread), the web-dubbing plugin and its bridge service, and the two
desktop shortcuts are all the same as in v2.0.
