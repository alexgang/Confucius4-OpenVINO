本节汇总 **v2.2** 相对 **v2.1** 的变化。

> ⚠️ **v2.2 修的是用户实测发现的 6 个问题**（CUDA 语音无声 / 离线提示「无参考音色」/
> 卡顿 / 克隆约 10 s 一次 / 男声被女声播出 / 界面不紧凑）。
> 模型、插件能力与 **v2.1 完全一致**；**桌面快捷方式暂不改指**（用户抽听后再定）。

### ① TTS 选 CUDA 时语音输出不工作（修好）

根因是**两个 bug 叠加**：CUDA 后端只缓存了「预设 A 的参考音频」，**没缓存音色名**
⇒ 每句回落到预设 A 时把音色名清空 ⇒ 合成前的音色检查判成「没有可用的音色」
⇒ **每一句都失败**，请求根本没送到 CUDA 边车。

现在：CUDA 分支同时缓存音色名；回落时只换参考音频、不清空音色名；
音色检查对 CUDA 后端改为查「当前有没有参考音频」。

### ② 离线朗读在 CUDA 下提示「无参考音色」（修好）

与 ① 同根因。另加一条回归用例：CUDA 后端 + 音色 A，9 段全部成功。
另外：检测不到 CUDA 边车环境时，**下拉框里的 CUDA 选项会置灰并显示原因**
（不再让用户选了以后才发现没声音）。

### ③ 卡顿（合成吞吐 ≤ 播放消耗）

实测：MT 与 TTS 同在 NPU 时合成慢 25–30 %；但即使默认摆放，合成速度也只有约
1.0× 实时，而播放端按 1.0–1.3× 消耗缓冲 ⇒ **环形缓冲欠载**才是卡顿主因。

现在：
* 会话日志**每 30 s** 打一行机器可算的遥测
  （`asr_rtf / asr_backlog_s / mt_lat_p50 / tts_synth_rtf / uf_in_sentence_ms`）；
* 欠载拆成**句内**（听得见的断音）与**句间空闲**两个口径，并换算成毫秒；
* **预缓冲**按「句长 ×(1 − 1/(r·speed))」计算（r = 最近实测合成速度）；
* **倍速动态封顶** `speed ≤ 1/r`（合成跟不上时宁可滞后，也不靠加速把缓冲抽空；
  用户定的 1.30× 上限不变）；
* MT/ASR 与 TTS 同在 NPU 时，语音区**标黄提示**（不禁止）。

### ④ 语音克隆从「每 10 s 一次」改为「换人时才取样」

旧版里**两套克隆机制并存**（定时采集器 + 按句绑定），实际在跑的是定时采集器
⇒ 与说话人变化无关地每隔十几秒重克隆一次。现在**停用定时采集器**，
克隆只走「按句绑定」：新说话人取样首段 ≥1.5 s，3 s 时定稿，老说话人复用缓存。

### ⑤ 原始男声被女声播出（修好）

三处根因：GUI 构造 TTS 服务时**漏传克隆开关**；补标签路径**丢掉了「新说话人」标记**
（⇒ 新说话人永远不会被取样）；标签晚到时**一律回落预设 A**。
现在：GUI 补传克隆开关；新说话人登记后正常取样；标签未到时若已有克隆音色则
**沿用上一句的克隆音色**（没有克隆音色时才用预设 A）。

### ⑥ 界面更紧凑

不常用控件（识别语种 / 草稿译文 / 重试翻译 / 离线朗读 / 测试声音 / 显示说话人 /
三个分区的说明行）收进**可折叠的「高级」面板**；三个分区的说明行合并进状态栏
（悬停可见）；字幕区高度从 v2.1 的约 30 % 提升到**约 79 %**（≥ 70 %）；
窗口最小宽度 1024，1024 宽下无控件被截断。
